# ADR 0024 — La 1.0: Windows y Linux probados, rendimiento, en inglés, Homebrew y una web

**Fecha:** 2026-10-19 · **Estado:** aceptada · entrega 8 · matiza la [0007](0007-espanol-con-i18n.md)

## Contexto

La 1.0 nunca se había definido más allá de una línea de `siguiente.md` («DMG, NSIS, `.deb` y
AppImage; README con la tabla de descargas»), y cambió de número tres veces (entregas 6, 7 y 8,
ADR 0014, 0018 y 0023). Los cuatro instaladores ya salen de CI desde la v0.2.0. Lo que de verdad
separaba la 0.9.1 de una 1.0, según la deuda:

- **Windows y Linux de escritorio no se habían abierto nunca en un equipo**: tres filas Alta (el
  Estudio, el MCP y su empaquetado), más un posible fallo real (AVIF y JPEG XL con una carpeta
  temporal con tildes en Windows).
- **Fotos grandes sin medir**: cuatro filas Media de memoria y tiempo.
- El README, desfasado («Pre-release v0.2.0») y sin tabla de descargas.

## Decisión

Planteada con el cliente el 2026-10-19, en modo plan:

| Tema | Decisión |
|---|---|
| Windows y Linux | Pruebas guiadas en sus máquinas virtuales **ARM** (Windows ARM y Ubuntu ARM en VMPal, en un Mac M1, que solo virtualiza ARM). Las versiones **x64**, con **pruebas de humo automáticas** en las máquinas de GitHub (`humo.yml`) |
| Firma | **Sin firmar**, como hasta ahora ([ADR 0009](0009-sin-firmar.md)) |
| Rendimiento | **Medir y arreglar** lo que se pase de un Mac de 8 GB |
| Homebrew | **La CLI y la aplicación**: fórmula y cask en un tap propio, `webcafeina/homebrew-apolo` |
| Inglés | **Todo**: la ventana, la CLI, el MCP, los mensajes del núcleo, las notas y el README |
| Web | **GitHub Pages con dominio propio** (`apolo.webcafeina.com`), en español e inglés |

En cuatro partes, cada una con su versión:
- **8a** (v0.10.0): Windows y Linux, y el README;
- **8b** (v0.11.0): rendimiento;
- **8c** (v0.12.0): inglés;
- **8d** (1.0.0): Homebrew y la web.

**Matiza la 0007.** La 0007 decía «la CLI se queda en español; si se traduce, irá aparte». Ahora se
traduce, y también el MCP y los mensajes del núcleo. La documentación interna sigue en español.

## Alternativas descartadas

- **La 1.0 solo para macOS**, con Windows y Linux en beta. El cliente tiene cómo probar ARM, y
  Windows es el sistema de la mayoría.
- **Firmar ya.** Cuesta 99 $ al año en Apple y unos 10 $ al mes en Windows, y el README explica cómo
  abrirla. Los pasos siguen escritos y desactivados en `publicar.yml`.
- **Solo la interfaz en inglés.** El cliente prefirió todo.

## Consecuencias

- **Windows x64 no lo verá nadie con los ojos**: solo CI. Queda dicho en la deuda.
- El tap, su deploy key y Pages son publicaciones hacia fuera: se hacen con el sí del cliente en
  ese momento.
- El inglés en Rust son unas 330 cadenas y toca muchos ficheros. Va con pruebas de que los dos
  catálogos tienen las mismas claves.

## Verificación

Se irá llenando con cada entrega. Lo que vale para todas:
- `make comprobar` antes de subir;
- CI en verde antes de etiquetar;
- la revisión de siempre del borrador.

**8a** (v0.10.0 a v0.10.2): humo en verde en Windows x64 y Linux x64 y arm64; pruebas guiadas
del cliente en Ubuntu 26.10 ARM64 y Windows ARM. Las de Windows destaparon dos fallos que CI no
veía (las DLL de Visual C++ y el manifiesto de la ventana), arreglados y vigilados ahora por el
humo. **No se probó**: actualizar desde la banda en Windows (las versiones anteriores no
arrancaban) ni un agente de verdad en Windows o Linux de escritorio.

**8b** (v0.11.0): `scripts/banco.sh` antes y después, con 200 fotos de 24 MP: todo por debajo de
2,3 GB (antes, hasta 6 GB), docs/rendimiento.md. `make equivalencia` igual, y la nota SSIMULACRA 2
igual bit a bit que la de libjxl. **No se midió** en un Mac ni en Windows: solo en el VPS, Linux.
